# RISK-ZERO 운영·개인정보·제어 정책 초안

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v0.4 |
| 기준일 | 2026-08-11 |
| 적용 범위 | 시청각 발화 검증 캡스톤 MVP |
| 상태 | 팀 검토 전 초안 |

## 1. 목적

RISK-ZERO는 음성 도어락 제어 요청이 현장 사람의 실제 발화인지 확인하는 보조 검증 시스템이다. 카메라 영상과 마이크 음성의 시간 일치, 화면 속 활성 화자, 재생·합성 의심, 랜덤 문구 일치를 함께 본다.

이 시스템은 사람의 신원, 관계, 의도나 범죄 여부를 판단하지 않는다. 시청각 검증만으로 상용 도어락을 운영하지 않으며, 캡스톤에서는 문 모형과 DEMO 데이터로 제한한다.

## 2. 기본 원칙

- 입력이 부족하거나 결과가 애매하면 문을 열지 않는다.
- PASS 한 번이 계속 유효하지 않도록 제어 허용시간을 짧게 둔다.
- 음성과 영상은 같은 장치 시계로 캡처하고 시간 동기화 상태를 함께 보낸다.
- 화면의 신뢰도는 신원 확률이 아니라 해당 판정 근거의 품질 지표로 표시한다.
- DEMO 결과와 실제 모델 결과를 DB와 화면에서 구분한다.
- 원본·후처리 영상은 필요한 범위와 기간만 보관한다.

## 3. 역할

| 역할 | 책임 |
| --- | --- |
| HW·모델 담당 | 동시 캡처, 타임스탬프, 사람·입술·음성·싱크 수치, 후처리 영상 생성 |
| SW 담당 | 데이터 계약, API, DB, 모바일·웹 화면, 제어 게이트, 로그 |
| 정책 담당 | 촬영 안내·동의, 보존·삭제, 시험 시나리오, 성능·한계 표기 |
| 팀 책임자 | 실제 사람 촬영과 문 모형 시험 승인, 중단 결정 |

## 4. 입력·출력 정책

### 4.1 필수 입력

- 제어 의도, ASR transcript·confidence, 요청·만료 시각, nonce
- 사람 존재, 얼굴 수, 입술 가시성, 음성 존재
- AV offset, sync confidence, active speaker score
- audio/visual spoof score
- challenge 일치 여부
- 음성·영상 품질, 시계 동기화 여부
- 모델·정책·스키마 버전

SW는 원시 마이크 파형과 센서 신호를 직접 분석하지 않는다. 하드웨어·모델 계층의 후처리 수치와 사건 영상만 받는다. 새 모델은 `models.py`의 어댑터 인터페이스를 구현하고 기존 데이터 계약을 유지한다.

### 4.2 판정

| 판정 | 의미 | 문 제어 |
| --- | --- | --- |
| `PASS` | 필수 조건이 모두 충족됨 | 짧은 유효시간 동안만 허용 |
| `BLOCK` | 재생·불일치·재사용 등 명확한 차단 사유 | 불허 |
| `INCONCLUSIVE` | 가림·노이즈·결측 등 판단 자료 부족 | 불허, 재시도 또는 앱 확인 |
| `PENDING` | 아직 처리되지 않음 | 불허 |

초기 정책값은 AV offset ±200ms, sync confidence 0.75 이상, active speaker 0.70 이상, audio spoof score 0.45 미만, 얼굴 1명, challenge 15초, PASS 게이트 3초다. 이 값은 캡스톤 시험용이며 데이터 수집 후 바꾼다.

### 4.3 반드시 차단하는 경우

- 요청·challenge·제어 토큰 만료
- 같은 nonce 또는 제어 토큰 재사용
- 얼굴 없음 또는 여러 얼굴
- 사람·음성·입술 필수 근거 누락
- 시계 동기화 실패
- AV offset 허용 범위 초과
- 재생·합성 의심 점수 초과
- PASS와 제어 출력의 요청 ID가 다름
- 모델 오류, 예외, 필수 필드 파싱 실패

## 5. Challenge-response 정책

랜덤 문구는 녹화 직전에 발급하고 15초 동안 한 번만 사용한다. 문구, challenge ID, nonce, 발급·만료·사용 시각을 기록한다. 고정 문구만 반복하면 미리 녹음한 영상에 취약하므로 실제 시험에서는 문구 목록과 순서를 주기적으로 바꾼다.

ASR transcript와 문구 비교는 보조 근거다. 입모양으로 문장을 완전히 복원하는 기능으로 설명하지 않는다. 발음 오류나 소음으로 문구 일치가 불확실하면 `INCONCLUSIVE`로 처리한다.

## 6. 제어 안전 정책

- 검증과 물리 출력은 `ActuationGate`로 분리한다.
- PASS 결과에는 request ID, verification ID, nonce, validUntil을 묶는다.
- 게이트는 만료, 재사용, ID 불일치, PASS 이외의 판정을 거부한다.
- 모형 시험에서는 `MockActuator`를 사용하고 실제 전기 잠금장치에 직접 연결하지 않는다.
- 전원 재부팅, 통신 끊김, 앱 종료 상태에서 기본 출력은 잠금 유지다.
- 내부에서 나갈 수 있는 수동 해제 수단을 항상 유지한다.

## 7. 개인정보·영상정보

카메라 영상, 목소리, 얼굴·입술 특징은 개인을 식별하거나 식별 가능하게 만들 수 있는 민감한 자료로 취급한다.

- 시험 참여자에게 목적, 항목, 기간, 접근자, 철회·삭제 방법을 먼저 알린다.
- 공동주택 복도 등 공용공간은 설치 권한과 촬영 범위를 별도로 확인한다.
- 문 바깥의 불필요한 공간과 이웃 출입문이 잡히지 않게 화각을 제한한다.
- 모델 개발용 데이터와 발표용 영상을 분리한다.
- 발표 자료에는 얼굴·음성을 비식별 처리하거나 사전 동의를 받는다.
- 클라우드 업로드는 기본으로 사용하지 않는다.

## 8. 보존·삭제

| 자료 | 캡스톤 기본값 | 처리 |
| --- | --- | --- |
| 브라우저 수집 테스트 | 페이지 종료 전까지 | 사용자가 저장하지 않으면 메모리에서 제거 |
| 후처리 사건 영상 | 최대 7일 또는 500MB 중 먼저 도달 | 오래된 파일부터 삭제 |
| 검증 수치·판정 | 학기 종료 후 30일 | 통계 익명화 후 원본 삭제 |
| challenge·nonce·제어 로그 | 학기 종료 후 30일 | 재사용 시험 확인 후 삭제 |
| 발표용 동의 자료 | 동의서에 적은 기간 | 기간 종료 또는 철회 시 삭제 |

현재 모바일에는 500MB 용량 정리가 구현되어 있고 7일 자동 삭제는 아직 구현 전이다. 구현되지 않은 보존 규칙을 동작 중인 기능처럼 설명하지 않는다.

## 9. 접근·보안

- 실제 장치 연결 전 장치별 키와 요청 서명을 추가한다.
- 모바일 DB와 영상 파일은 운영체제 앱 전용 저장소를 사용한다.
- 로그에는 원문 transcript와 파일 경로가 포함될 수 있으므로 디버그 로그 공유를 제한한다.
- Git 저장소에 실제 참여자 영상, 음성, 토큰, 비밀키를 올리지 않는다.
- 모델 파일의 출처·라이선스·해시를 기록한다.
- 보안 문제 발견 시 촬영과 문 모형 시험을 중단하고 해당 데이터를 격리한다.

## 10. 시험·성능 공개

정상 발화, 스피커 재생, 화면 재생, AV 지연, 여러 얼굴, 입술 가림, 노이즈, 합성 음성, nonce 재사용을 분리해 시험한다. 같은 사람이 같은 환경에서 반복한 결과만으로 일반 성능을 주장하지 않는다.

최소 보고 항목은 시나리오별 수, PASS/BLOCK/INCONCLUSIVE 혼동행렬, FAR, FRR, APCER, BPCER, 처리시간, 실패 원인이다. threshold와 모델·정책 버전이 바뀌면 이전 결과와 섞지 않는다.

## 11. 변경 관리

다음 항목이 바뀌면 문서와 코드 버전을 함께 올린다.

- 입력 metric과 단위
- 모델·가중치·threshold
- challenge 문구·만료시간
- PASS 제어 유효시간
- 영상 보존기간·촬영범위
- 실제 장치·통신 방식

실제 사람 촬영, 외부 서버 전송, 문 모형 이외의 잠금장치 연결은 팀 책임자와 정책 담당의 재검토 후 진행한다.
