# RISK-ZERO 현재 구현 현황

- 기준 버전: Mobile v0.2.0
- 기준일: 2026-07-27
- 범위: 대학 캡스톤 MVP

## 전체 흐름

```text
하드웨어(분석·영상 후처리)
  → ModuleGateway 계약
  → 임시 이벤트 버퍼
  → 모바일 동기화
  → 영상 파일 저장 + SQLite 기록
  → 위험도 결과(pending 또는 DEMO)
  → 모바일 조회·분류·알림
```

웹은 하드웨어 연결 전 API와 모니터링 화면을 시험하기 위한 별도 개발 경로다. 모바일의 주 저장소는 기기 내부 SQLite이며 영상은 DB가 아닌 앱 전용 파일 저장소에 둔다.

## 구현 완료

| 영역 | 현재 동작 |
| --- | --- |
| 모바일 홈 | 4개 DEMO 시나리오, 위험 단계·점수·수치·대응 미리보기 |
| 이벤트 조회 | 최근 이벤트, 월간 캘린더, 날짜 선택, 시간대·위험 단계 그룹 |
| 상세·영상 | 이벤트 상세, 재생·일시정지·10초 이동·전체화면 인터페이스 |
| 로컬 영상 | 임시 파일을 앱 저장소로 복사, 크기 검증, DB 경로 저장, 500MB 초과 시 오래된 파일부터 정리 |
| 분류·검색 | 거주자·방문객·배달·의심·침입·기타, 오탐·중요 표시, 메모, 제목·내용·메모 검색 |
| 기기 알림 | 주의·경고·고위험별 설정, 동일 단계 기본 10분 제한, 이벤트 중복 방지, 확인 완료 처리 |
| 장치 관리 | 여러 장치 프로필 등록, 통신 방식, 배터리·모듈 저장공간·동기화 상태 표시, 장치 데이터 삭제 |
| 모바일 DB | SQLite 스키마 v3, 13개 테이블, 중복 이벤트와 순번 관리 |
| 모듈 동기화 | sequence 기반 pull, 영상·수치 저장 뒤 ACK, 재연결·버퍼 유실 모델 |
| 웹 | 센서 이벤트·사건·장치·피드백 API, D1 스키마·더미 데이터, 웹 모니터 |

## 연결 대기

| 영역 | 남은 작업 |
| --- | --- |
| 하드웨어 통신 | 실제 BLE 또는 Wi-Fi `ModuleGateway` 구현과 실기기 통합 |
| 영상 입력 | 하드웨어가 만든 실제 후처리 영상 파일과 체크섬 전달 |
| 위험도 엔진 | 가중치·임계값 확정, 버전 저장, 실험 데이터 검증 |
| 알림 | 앱이 닫힌 동안 모듈에서 이벤트를 깨우는 백그라운드 통신, 원격 보호자 푸시 |
| 계정·보안 | 사용자·장치 인증, 요청 서명, 역할별 접근, 키 폐기 |
| 운영 자동화 | 기간 기반 삭제, 암호화·백업·감사, 조용한 시간대 |
| 외부 대응 | 112 신고와 도어락 제어는 안전·정책 검토 후 별도 구현 |

## 테스트 기준

- 모바일 TypeScript 검사
- 모바일 단위 테스트 21개
- Android·Web Expo 번들 생성
- SQLite 스키마 v3의 13개 테이블 생성
- 모바일 화면 크기 390×844에서 주요 흐름 확인
- GitHub Actions에서 Android release APK 빌드

DEMO 점수 `14`, `46`, `68`, `88`은 화면과 데이터 흐름을 확인하기 위한 고정값이다. 실제 안전 판단의 성능을 뜻하지 않는다.
