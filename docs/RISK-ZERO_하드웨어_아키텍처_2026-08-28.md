# RISK-ZERO 하드웨어 아키텍처

- 기준일: 2026-08-28
- 상태: 하드웨어팀 구현 계획 반영본
- 대상: 대학 캡스톤 MVP
- FPGA: Digilent Arty A7-100T, `xc7a100tcsg324-1`

## 현재 결정

기존 XIAO ESP32-S3 Sense 또는 AI Thinker ESP32-CAM의 전체 프레임을 UDP/SPI로 FPGA에 보내는 구조는 현재 구현 기준에서 제외한다. 카메라는 Parallel DVP 인터페이스로 FPGA에 직접 연결하고, ESP32-S3 DevKitC는 Door Hub 역할만 담당한다.

```text
PIR
→ ESP32-S3 Door Hub
→ EVENT_START(event_id)
→ Arty Vision Domain 활성화
→ 외부 Parallel DVP Camera 활성화
→ FPGA 직접 픽셀 수신·영상 분석
→ 결과/선택 Snapshot
→ ESP32-S3 Door Hub
→ Wi-Fi
→ 앱·서버
```

Arty는 이벤트마다 전원을 끄고 켜지 않는다. FPGA 구성과 Safety Domain은 계속 유지하고 Camera와 Vision Domain만 이벤트에 따라 대기·활성 상태를 전환한다.

## 장치별 책임

| 장치 | 책임 |
| --- | --- |
| ESP32-S3 Door Hub | PIR 입력, 중복 이벤트 제거, `event_id`, 앱·서버 통신, authorization, FPGA heartbeat·auth·request, 결과·Snapshot 중계 |
| Arty A7 Safety Domain | Reed #2, Tamper, E-stop, heartbeat, authorization/request를 독립 검사하고 제한된 개방 펄스 생성 |
| Arty A7 Vision Domain | 카메라 제어, DVP 픽셀 수신, 배경 차분, bbox·중심점·구역·체류·종료 배경 비교 |
| 외부 DVP Camera | `D[7:0]`, `PCLK`, `VSYNC`, `HREF` 픽셀 출력과 `XCLK`, `RESET`, `PWDN`, SCCB/I2C 제어 입력 |
| 앱·서버 | 하드웨어 결과·Snapshot·안전 결정 표시와 기록. FPGA나 액추에이터 직접 제어 금지 |

## FPGA 책임 분리

```text
FPGA
├─ Safety Domain
│  ├─ 별도 system clock/reset
│  ├─ auth/req/heartbeat toggle 동기화
│  ├─ Reed #2/Tamper/E-stop 직접 입력
│  └─ default-deny unlock_allow_pulse
└─ Vision Domain
   ├─ Camera wake/configuration/integrity
   ├─ PCLK domain DVP RX
   ├─ Async FIFO 또는 명시적 CDC
   ├─ GRAY8·B_ref·background difference
   ├─ noise filter·bbox·centroid·3×3 zone·timeline
   └─ B_end 비교·Snapshot buffer
```

Vision 결과는 Door Hub에 전달되는 관찰값이다. Vision RTL에서 `unlock_allow_pulse`로 직접 연결하는 경로는 만들지 않는다. Camera PCLK 정지, Vision reset 또는 Camera fault가 Safety FSM의 clock과 직접 안전 입력을 막아서는 안 된다.

## 전원 정책

대기 상태:

```text
ESP32-S3 Door Hub  ON
FPGA configuration 유지
Safety Domain      ON
Vision Domain      idle 또는 clock enable=0
Camera             PWDN/standby, 필요 시 외부 load switch OFF
```

방문 이벤트:

```text
EVENT_START
→ Vision clock enable
→ Camera PWDN 해제·XCLK·reset·SCCB 설정
→ frame sync와 geometry 확인
→ capture/process
```

종료:

```text
PIR LOW + visitor absent N frames
→ B_end 획득
→ B_ref 비교
→ 결과/Snapshot 전송
→ Camera sleep
→ Vision idle
```

FPGA 전체 전원 차단은 MVP에서 사용하지 않는다. 미구성 상태의 actuator 안전을 보장하는 외부 supervisor와 interlock을 추가한 이후에만 별도 저전력 실험으로 검토한다.

## 카메라 입력 계약

초기 후보는 Parallel DVP 모듈이다. MIPI CSI-2는 D-PHY와 packet decoder가 필요하므로 첫 시연 범위에서 제외한다.

```text
Camera → FPGA: D[7:0], PCLK, VSYNC, HREF/HSYNC
FPGA → Camera: XCLK, RESET, PWDN, SCCB/I2C
```

초기 분석 조건:

- 우선 해상도 `160×120`, 후속 `320×240`
- 내부 분석 포맷 `GRAY8`
- raster scan
- PCLK domain에서 multi-bit pixel bus capture
- processing clock이 다르면 asynchronous FIFO 사용
- frame width/height, PCLK/VSYNC/HREF 활동과 SCCB read-back 확인

카메라 모델, I/O 전압, 실제 핀, 출력 포맷, XCLK/PCLK와 frame rate는 확정하지 않았다. 구매 모듈 회로도와 데이터시트를 확인하기 전에는 XDC나 RTL 상수로 임의 고정하지 않는다.

## Vision 최소 파이프라인

```text
DVP RX
→ Pixel format/GRAY8
→ B_ref read
→ absolute difference
→ threshold
→ noise filter
→ foreground accumulation
→ bbox/centroid
→ 3×3 zone·timeline·width/height delta
→ result register
→ ESP32-S3 result/Snapshot link
```

종료 배경은 다음 값으로 판단한다.

```text
changed_pixel = |B_end - B_ref| > TH_bg_pixel
background_change_ratio = changed_pixel_count / valid_roi_pixel_count
```

임계값은 실제 설치 영상 전에는 결정하지 않는다. 문 열림, 조명, 그림자와 카메라 흔들림을 포함한 데이터로 오탐과 누락을 측정한 뒤 정한다.

## Safety 제어 계약

Door Hub와 Safety Domain은 대용량 Vision 통신과 분리된 toggle/GPIO 제어면을 사용한다.

입력:

- `auth_toggle`: 새 authorization
- `req_toggle`: authorization 소비·실행 요청
- `heartbeat_toggle`: Door Hub 생존
- `door_closed_direct`: FPGA 직접 Reed #2
- `tamper_detected`: 강제 조작
- `estop_n`: 비상 차단
- `clear_fault`: 정상 조건에서 명시적 fault 해제

출력:

- `ack_toggle`
- `decision_code`: NONE/ALLOW/BLOCK/ABORT
- `block_reason`
- `auth_armed`
- `fault_latched`
- `unlock_allow_pulse`

우선순위는 E-stop·fatal fault, Tamper, 직접 문 상태, heartbeat, authorization, request 순서다. 개방 펄스 중 직접 입력이 unsafe로 바뀌면 동기화 직후 펄스를 종료하고 ABORT를 래치한다.

## Vision 통신 초안

영상 전체를 ESP32에서 FPGA로 보내지 않는다. ESP32-S3는 SPI Master, FPGA는 SPI Slave로 두고 `DATA_READY` 또는 IRQ를 추가하는 방식을 우선 검토한다.

- ESP32→FPGA: `EVENT_START`, `EVENT_END`, `event_id`, 설정·상태 요청
- FPGA→ESP32: Vision result, health/status, 선택 Snapshot
- Safety auth/request/heartbeat: 전용 toggle/GPIO

결과 packet에는 최소한 `protocol_version`, `event_id`, `frame_id`, 이벤트 상대 시각, visitor flag, object count, bbox, centroid 변화, primary zone, zone mask, first/last seen, dwell, background change와 vision status를 포함한다. Snapshot은 별도 payload와 CRC로 전송한다. 정확한 SPI mode·clock·register offset·핀은 결정 필요 항목이다.

## 첫 시연 범위

Vision:

```text
PIR → event_id → Camera wake → 160×120 GRAY8 DVP
→ B_ref 차분 → 단일 foreground bbox·centroid → 3×3 zone
→ result packet → ESP32 표시
→ B_end 비교 → 필요 Snapshot → Camera sleep
```

Safety:

```text
Door Hub heartbeat/auth/request
+ Reed #2/Tamper/E-stop
→ FPGA Safety Gate
→ ALLOW/BLOCK LED
```

첫 시연에서는 MIPI, FPGA 전체 power cycling, FPGA JPEG encoder, VGA 이상, 다중 객체 CCL과 실제 Solenoid를 제외한다. 액추에이터 통합 전까지 LED를 사용한다.
