# RISK-ZERO 시청각 데이터 수집 가이드

- 버전: v0.1
- 작성일: 2026-08-11
- 범위: 캡스톤 파일럿 시험

## 1. 목적

같은 카메라와 마이크로 정상 발화와 공격 상황을 반복 촬영하고, 영상마다 촬영 조건을 빠뜨리지 않고 기록한다. 이 단계의 자료는 모델 학습보다 **시험 절차 확인과 기준선 측정**에 먼저 사용한다.

웹의 `/capture` 화면은 영상을 서버로 올리지 않는다. 녹화가 끝나면 영상 파일과 같은 이름의 JSON 파일을 브라우저에서 각각 내려받는다. 두 파일을 한 쌍으로 보관한다.

## 2. 촬영 순서

1. 실명이 아닌 참여자 코드(`P01`, `P02` 등)를 정한다.
2. 촬영 유형을 선택하고 화면의 랜덤 문구를 확인한다.
3. 카메라·마이크를 켜고 얼굴과 입 주변이 보이는지 확인한다.
4. 녹화를 시작한 뒤 문구를 한 번 읽는다. 녹화는 최대 8초 후 자동 종료된다.
5. 영상을 재생해 소리와 영상이 함께 저장됐는지 확인한다.
6. `영상 저장`과 `정보 JSON 저장`을 모두 누른다.
7. 파일 두 개를 참여자별 폴더에 옮긴다.

권장 폴더 예시는 다음과 같다.

```text
RISK-ZERO-dataset/
  P01/
    risk-zero_20260811T030405Z_bona-fide_64cae736-e53.webm
    risk-zero_20260811T030405Z_bona-fide_64cae736-e53.json
```

원본 영상은 Git 저장소에 올리지 않는다. 별도의 접근 제한 폴더에 보관한다.

전체 폴더를 검사하고 목록을 만들 때는 다음 명령을 사용한다.

```powershell
python -m edge.risk_zero_av --index-dataset C:\RISK-ZERO-dataset --output C:\RISK-ZERO-dataset\dataset-index.json
```

생성된 인덱스에는 상대경로와 실험 메타데이터만 들어가며 영상 내용은 복사되지 않는다. `invalidPairs`가 0인지 확인한 뒤 분석 단계로 넘긴다.

## 3. 현재 촬영 유형

| ID | 화면 표시 | 촬영 방법 |
| --- | --- | --- |
| `bona-fide` | 정상 발화 | 참여자가 화면 앞에서 현재 문구를 직접 읽음 |
| `audio-replay` | 녹음 음성 재생 | 사람 대신 미리 녹음한 음성을 스피커로 재생 |
| `screen-replay` | 화면 영상 재생 | 휴대전화나 모니터로 이전 발화 영상을 재생 |
| `av-delay` | 음성·입모양 지연 | 영상과 음성의 시작 시점을 의도적으로 어긋나게 재생 |
| `mouth-occlusion` | 입 주변 가림 | 손이나 마스크로 입 주변을 일부 가린 상태에서 발화 |
| `background-noise` | 배경 소음 | 음악·대화 소음 등을 함께 재생하며 발화 |

파일럿에서는 참여자 8~12명, 유형별 5회 이상을 권장한다. 처음부터 많은 양을 모으기보다 참여자 2명으로 전 과정을 시험한 뒤 확대한다.

## 4. JSON 규격

`schemaVersion`은 `av-capture-manifest/1`이다.

```json
{
  "schemaVersion": "av-capture-manifest/1",
  "sessionId": "64cae736-e532-4692-97d6-21fd87fb39f1",
  "participantCode": "P01",
  "scenario": "bona-fide",
  "challengePhrase": "초록 우산 문 열어",
  "capturedAt": {
    "started": "2026-08-11T03:04:05.123Z",
    "ended": "2026-08-11T03:04:09.373Z",
    "durationMs": 4250
  },
  "media": {
    "fileName": "risk-zero_20260811T030405Z_bona-fide_64cae736-e53.webm",
    "mimeType": "video/webm;codecs=vp8,opus",
    "sizeBytes": 4096
  },
  "source": "browser-local",
  "verificationStatus": "not_evaluated"
}
```

`verificationStatus`는 실제 모델을 실행하기 전까지 항상 `not_evaluated`다. 웹 화면에서 임의의 싱크 점수나 PASS/BLOCK 결과를 만들지 않는다.

## 5. 데이터 분리와 품질 확인

- 같은 참여자의 영상이 개발 세트와 최종 테스트 세트에 동시에 들어가지 않게 참여자 단위로 나눈다.
- 촬영 실패, 무음, 얼굴 미검출 여부는 원본을 지우지 말고 별도 품질 점검표에 기록한다.
- 정상·공격 유형 수가 지나치게 한쪽으로 치우치지 않게 한다.
- 거리, 조명, 재생 장치, 소음 크기처럼 JSON에 아직 없는 조건은 실험 일지에 기록한다.
- 모델 임계값은 개발 세트로 정하고 최종 테스트 세트에서는 바꾸지 않는다.

## 6. 개인정보 원칙

- 촬영 전에 목적, 보관 기간, 열람자, 삭제 요청 방법을 안내하고 동의를 받는다.
- 참여자 코드와 실명 대응표는 영상 폴더와 분리한다.
- 시연용 공개 저장소에는 얼굴·음성이 포함된 원본을 올리지 않는다.
- 수집 목적이 끝나거나 참여자가 요청하면 원본, 복사본, 파생 파일을 함께 삭제한다.
- 타인의 영상·음성을 이용한 재생 공격 시험은 당사자 동의가 있는 자료만 사용한다.

## 7. 이번 구현의 경계

현재 화면은 로컬 동시 녹화와 메타데이터 생성을 지원한다. 카메라·마이크 동기 정확도 측정, 모델 학습, 자동 라벨 검증, 서버 업로드, DB 적재는 아직 구현하지 않았다.
